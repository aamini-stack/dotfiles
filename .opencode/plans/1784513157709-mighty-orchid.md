# Plan: `aamini.jj` — first-class Jujutsu support as a Herdr plugin

## Context

Herdr's maintainer declined built-in jj support ("can be a plugin") pointing at v0.7.4
features: plugin panes (`placement = "popup"`), custom sidebar row layouts with `$token`
metadata, and `pane|workspace report-metadata`. We build our own plugin `aamini.jj`,
reusing the existing Python CLI at `tools/python/cli` (`herdr-ws open/close`, cd-guard),
and drop `nathanflurry.jj-workspace` after cutover.

Verified against live docs (herdr.dev, updated Jul 18 2026) and local files.

## Prerequisites

1. Bump herdr: `.config/mise/config.toml:56` `herdr = "0.7.3"` → `"0.7.4"`, `mise install herdr`,
   restart herdr server. (mise.lock refreshes; backend `github:ogulcancelik/herdr`.)
2. Post-upgrade smoke checks:
   - `herdr api schema --json` contains `workspace.report_metadata` and `popup.close`
   - `herdr workspace report-metadata --help` works
   - `fzf`, `jj >= 0.43`, and the `tools/python/cli` console scripts are on PATH in the
     plugin spawn environment

## Language: Python (+ fzf for popup UIs)

No `[[build]]` step → `herdr plugin link` works with zero compilation. All domain logic
(herdr JSON wrapper, labels, cd-guard) already exists and is pytest-covered in
`tools/python/cli`. Picker/wizard popups use `fzf` as a subprocess UI (~50 lines vs 689
lines of ratatui in nathanflurry's plugin).

## Layout

```
tools/herdr-jj/
└── herdr-plugin.toml        # the only file — no bin/
```

One console script `herdr-jj` is added to the existing `tools/python/cli` pyproject
(next to `herdr-ws`), with argparse subcommands: `new`, `remove`, `pick`, `wizard`,
`picker`, `reporter`. Every manifest command invokes it with different args
(`["herdr-jj", "wizard"]` etc.) — argv arrays take args fine, and PATH resolution is
already proven since `herdr-ws` resolves today. Real code lives in
`tools/python/cli/src/cli/plugin/` (`wizard.py`, `remove.py`, `picker.py`,
`reporter.py`) so it's covered by the existing pytest suite. Plugin code imports existing
`open.py` (`open_workspace`, `herdr_label_for`), `close.py` (`close_workspace`),
`guard.py`, `herdr.py`. `herdr-ws` stays the canonical human CLI; nothing moves.

### `herdr-plugin.toml`

```toml
id = "aamini.jj"
name = "jj workspaces"
version = "0.1.0"
min_herdr_version = "0.7.4"
description = "Jujutsu workspace support: create, remove, pick, agent spawn, sidebar status."
platforms = ["linux", "macos"]

[[actions]]
id = "new"
title = "New jj workspace"
contexts = ["workspace", "global"]
command = ["herdr-jj", "new"]

[[actions]]
id = "remove"
title = "Remove jj workspace"
contexts = ["workspace"]
command = ["herdr-jj", "remove", "--current"]

[[actions]]
id = "pick"
title = "Switch jj workspace"
contexts = ["workspace", "global"]
command = ["herdr-jj", "pick"]

[[panes]]
id = "picker"
title = "jj workspaces"
placement = "popup"
command = ["herdr-jj", "picker"]

[[panes]]
id = "name-wizard"
title = "New jj workspace"
placement = "popup"
command = ["herdr-jj", "wizard"]

[[events]]
on = "workspace.created"
command = ["herdr-jj", "reporter", "ensure"]

[[events]]
on = "workspace.closed"
command = ["herdr-jj", "reporter", "refresh-once"]
```

Actions have no TTY, so `herdr-jj new` / `herdr-jj pick` call
`$HERDR_BIN_PATH plugin pane open aamini.jj <pane>` (mirrors nathanflurry's
action→wizard split). Install: `herdr plugin link ~/dotfiles/tools/herdr-jj`.

## Features

### 1. Create (prefix+shift+a)
- `herdr-jj new`: resolve repo cwd from `HERDR_PLUGIN_CONTEXT_JSON` / active pane cwd →
  `jj root` to confirm; open `name-wizard` popup. Pass context via
  `$HERDR_PLUGIN_STATE_DIR/picker-context.json` if popup env inheritance is insufficient
  (popups get no `HERDR_PANE_ID`; they do get `HERDR_ACTIVE_*` — verify in 0.7.4).
- `herdr-jj wizard` (in popup TTY): read name via `input()`; dest = sibling of repo root
  `<repo>-<name>`; `jj workspace add <dest> --name <name>` (default rev; `-r main@origin`
  fallback later); call `open_workspace(dest)` directly (same flow as `herdr-ws open`),
  exit → popup closes, user lands in the new workspace.

### 2. Agent spawn
Zero new code: `open_workspace` (tools/python/cli/src/cli/open.py:61) already creates the
`ws-<project>-<name>` herdr workspace, splits left (`mise run bootstrap` if the task
exists) / right (`opencode`), arms cd-guard. Plugin reuses it verbatim.

### 3. Remove (prefix+d)
`herdr-jj remove --current`: herdr workspace cwd → `jj root` + `jj workspace list` to find the
jj name; refuse on primary/default workspace; popup confirm; then in order:
`close_workspace()` (closes herdr side + disarms guard) → `jj workspace forget <name>` →
`rm -rf <dir>` with a safety check that dir is the expected sibling path (forget does NOT
delete the directory).

### 4. Picker (prefix+a)
`herdr-jj picker` in popup: `jj workspace list` (verify template keywords on jj 0.43; else
parse default output + per-workspace `jj log -r <name>@ -T change_id.shortest()`);
fzf lines `<name>\t<change>\t<dirty>\t<herdr-label or —>`, preview = `jj log`; on select:
focus existing herdr workspace (match via `herdr_label_for`) or `open_workspace(path)`.
Extra fzf binds: `ctrl-d` remove highlighted, `ctrl-n` new.

### 5. Sidebar tokens — reporter daemon (hardest part)

Something must repeatedly run jj and call `workspace report-metadata`. Design: one daemon
per herdr server, event-armed, poll+subscribe hybrid.

- **Arm**: `[[events]] workspace.created` → `herdr-jj reporter ensure`. Lockfile
  `$HERDR_PLUGIN_STATE_DIR/reporter-<sha1(socket_path)>.lock` `{pid, socket_path}`; alive +
  same socket → exit; else spawn `reporter run` detached (log to state dir). Also call
  `ensure` from `herdr-jj new` and `herdr-jj pick` (cold start). Server restart is covered: first
  workspace created re-arms; stale lock w/ dead pid replaced.
- **Loop**: subscribe on `$HERDR_SOCKET_PATH` to `workspace.created/closed/focused` (cheap
  invalidation); scan `workspace list` cwds for `jj root` (cached map). Refresh triggers:
  subscribed event → refresh that workspace; else poll focused workspace every 5s, others
  every 30s. Report only on change, via CLI:
  `herdr workspace report-metadata <ws_id> --source aamini.jj --token jj_status="<v>" --seq <n> --ttl-ms 90000`
  (TTL 90s self-cleans stale tokens if daemon dies; `--seq` prevents out-of-order clobber).
- **Exit**: socket connect fails repeatedly / workspace list errors >30s → server gone, exit.
- **Token v1** (≤80 chars): `change_id.shortest()` + dirty marker from one call:
  `jj log --no-graph -r @ -T 'change_id.shortest() ++ " " ++ if(empty, "✓", "●")'`
  e.g. `kxyzqptm ●`. Ahead/behind vs `main@origin` is v1.1.

Replace the three `nathanflurry.jj-workspace` bindings (lines 92–108):

```toml
[[keys.command]]
key = "prefix+shift+a"
type = "plugin_action"
command = "aamini.jj.new"
description = "JJ workspace: create"

[[keys.command]]
key = "prefix+a"
type = "plugin_action"
command = "aamini.jj.pick"
description = "JJ workspace: switch"

[[keys.command]]
key = "prefix+d"
type = "plugin_action"
command = "aamini.jj.remove"
description = "JJ workspace: remove"

[ui.sidebar.spaces]
rows = [["state_icon", "workspace"], ["branch", "git_status", "$jj_status"]]
```

(`$`-prefix in row entries confirmed in docs; `$jj_status` = workspace metadata token.)
Then `herdr plugin unlink nathanflurry.jj-workspace` and `herdr server reload-config`.

## Verification

1. `herdr plugin link tools/herdr-jj` → `herdr plugin list` shows `aamini.jj`, no warnings.
2. `herdr plugin action invoke aamini.jj.pick|.new` — popup opens, fzf lists, select focuses/creates.
3. Keybindings prefix+a / prefix+shift+a / prefix+d live in a session.
4. Sidebar: create jj workspace, edit a file → focused Space row shows `●` within ~5s;
   `jj new` → `✓`. `kill <reporter pid>` → tokens clear within 90s (TTL);
   `herdr-jj reporter ensure` → tokens return.
5. Server restart → create/focus workspace → daemon re-spawns, tokens repopulate
   (metadata is not persisted; verify repopulation).
6. prefix+d on a jj workspace → herdr workspace closed, `jj workspace list` clean,
   directory gone, cd-guard roots pruned.
7. Full pytest suite in `tools/python/cli` passes.

## Risks / open questions

- Popup env inheritance in 0.7.4 (no `HERDR_PANE_ID`; has `HERDR_ACTIVE_*`) — fallback:
  action writes context JSON to state dir for the popup to read.
- `jj workspace list -T` template keywords on jj 0.43 are narrower than `jj log` — fall
  back to parsing + per-workspace `jj log`.
- Metadata not persisted across server restarts — accepted, mitigated by event re-arm + TTL.
- Local `herdr api schema` dump is 0.7.3; re-dump post-upgrade and gate reporter startup
  on `workspace.report_metadata` being present.
- Polling cost: ~1 `jj log` per 5s (focused) — fine; raise background interval if >10 jj
  workspaces.
