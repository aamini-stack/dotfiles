# herdr cd-guard: block `cd` outside the workspace root

## Goal
Shells running inside a herdr pane cannot `cd` outside the root directory of the herdr
workspace ("group") they belong to. Hard block + escape hatches, delivered as a zsh hook
(enforcement) + a thin herdr plugin (toggle/config/notifications).

## Why not a pure herdr plugin
Verified against herdr 0.7.3 docs + live API:
- Plugins only get keybinding **actions**, **event hooks** (workspace/tab/pane lifecycle,
  worktree events — there is **no cwd-changed event**), panes, and link handlers.
- A plugin process cannot veto `cd` (a shell builtin) in another pane's shell.
- Enforcement must live inside the pane's shell: a zsh `chpwd` hook gated on `HERDR_ENV=1`.

## Key facts (verified live)
- Pane env has `HERDR_ENV=1`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`, `HERDR_SOCKET_PATH`.
- API does **not** expose a workspace's `identity_cwd` (`workspace get/list` have no cwd field;
  only pane records have `cwd`). Therefore:
  - **Root = pane launch cwd**, captured as `$PWD` when `.zshrc` is sourced (for root panes this
    *is* the workspace root; for split panes it's the inherited cwd — documented limitation,
    fixable via the plugin's `set-root` override).
- Plugin config/state dirs follow `~/.config/herdr/plugins/{config,state}/<plugin_id>/`
  (precedent: `plugins/config/worktrunk/config.toml`). The hook reads state from the config dir.
- `.config/herdr/` is gitignored except `config.toml`, and the deleted `worktrunk` plugin left
  dangling keybindings — so the new plugin source must live in a **tracked** dir and be linked.

## Design

### 1. zsh hook — `.zshrc` (new section, only active when `HERDR_ENV=1`)
- At source time: `export HERDR_GUARD_ROOT="$PWD"` (pane launch cwd).
- State files in `~/.config/herdr/plugins/config/aamini.cd-guard/`:
  - `disabled` — workspace ids (one per line) where the guard is off.
  - `roots` — `<workspace_id>\t<abs path>` root overrides.
- `chpwd` hook (via `autoload -Uz add-zsh-hook; add-zsh-hook chpwd ...` — composes with the
  existing `preexec` etc. and catches `cd`, `pushd`, `popd`, zoxide `z`, `gr()`, `wt switch`,
  yazi `y`, `nvim()`-dirjump):
  - Allow if `$PWD` (logical) is under root, **or** `${PWD:A}` (resolved) is under `${root:A}`
    — permits symlink-inbound dirs like `~/.config/herdr -> dotfiles/.config/herdr`.
  - On violation: print `cd blocked: <dir> is outside workspace root <root> (use cd! to override)`,
    snap back with `builtin cd` to `$OLDPWD` if allowed else the root (recursion guard flag).
    Optionally fire `herdr notification show` if `notify = true` in the plugin config file.
  - Skip when: per-shell `HERDR_GUARD_DISABLED=1`, or workspace id listed in `disabled`.
- Escape hatches:
  - `cd! <dir>` — one-shot bypass (`builtin cd`).
  - `guard off|on|status` — per-shell toggle + prints root/mode.

### 2. Thin plugin — new tracked dir `tools/herdr-cd-guard/`
- `herdr-plugin.toml`: id `aamini.cd-guard`, `min_herdr_version = "0.7.0"`,
  `platforms = ["linux","macos"]`, actions only (no panes/events):
  - `toggle` (contexts `["workspace"]`) — add/remove `$HERDR_WORKSPACE_ID` in `disabled`;
    feedback via `"$HERDR_BIN_PATH" notification show`.
  - `set-root` (contexts `["workspace"]`) — write root override for the workspace from the
    focused pane's cwd (`pane current` cwd).
  - `status` — print root + enabled/disabled for current workspace.
- `toggle.sh`, `set-root.sh`, `status.sh` (bash, use `$HERDR_BIN_PATH`, `$HERDR_PLUGIN_CONFIG_DIR`).
- Install once: `herdr plugin link ~/dotfiles/tools/herdr-cd-guard`.
- `.config/herdr/config.toml`: add one `[[keys.command]]` `plugin_action` binding for
  `aamini.cd-guard.toggle` (pick a free key, e.g. `prefix+c` — verify against existing bindings
  `prefix+{a,d,shift+a,shift+d,shift+g}`).

## Files
- Edit: `.zshrc` (new "herdr cd guard" section, ~60 lines, HERDR_ENV-gated so macOS/remote
  shells without herdr are unaffected).
- Create: `tools/herdr-cd-guard/{herdr-plugin.toml,toggle.sh,set-root.sh,status.sh}`.
- Edit: `.config/herdr/config.toml` (one keybinding).
- Not in repo (runtime): `herdr plugin link`, plugin config dir state files.

## Interactions to be aware of
- `wt switch` / `wt remove` cd across jj workspaces → blocked by design (use jj-workspace
  plugin tabs/workspaces, or `cd!`).
- `z` (zoxide) jumps outside the root → blocked (intended).
- Non-interactive shells (agent tool calls, scripts) never source `.zshrc` → unaffected.
- `dev()` remote herdr sessions run the remote host's zshrc → guard absent there (fine).

## Verification
1. Pure-zsh harness (no herdr): `mkdir -p /tmp/ws/sub && cd /tmp/ws && HERDR_ENV=1 HERDR_WORKSPACE_ID=test zsh -ic 'cd sub; pwd; cd /; pwd; cd! /; pwd'`
   → expect `/tmp/ws/sub` ok, `cd /` blocked (still in `/tmp/ws/sub`), `cd! /` succeeds.
2. Symlink: from a dotfiles-rooted pane, `cd ~/.config/herdr` → allowed (resolves inside root).
3. Live in herdr: split a pane, try `cd ~`, `cd ..` above root → blocked; `guard off; cd ~` works;
   `guard on` re-enables.
4. Plugin: `herdr plugin link ~/dotfiles/tools/herdr-cd-guard` → `herdr plugin list` shows
   `aamini.cd-guard` with no warnings; invoke `aamini.cd-guard.toggle` via keybinding → toast +
   `disabled` file updated; new chpwd in that workspace is allowed; toggle again → blocked.
5. `herdr plugin action list --plugin aamini.cd-guard` shows toggle/set-root/status.
