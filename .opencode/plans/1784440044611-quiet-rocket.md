# Retire `code`; make `wt switch` the single workspace interface

## Rationale
dojjo's `switch` already does everything `code` was built for:
- bare `wt switch` → built-in fzf picker of all jj workspaces (numbered
  fallback when fzf is missing) — see `_pickWorkspace` in dojjo's
  switch_command.dart
- `wt switch <name>` → existing: post-switch hook; unknown: prompts to create
- `wt switch -c <name>` / `wt switch -` → create / previous
- hooks (`post-start`/`post-switch` → `herdr-ws-open '<path>' --project-path …`)
  do the herdr side: open/focus workspace, arm cd-guard. Unchanged.
- `wt switch` keeps its normal behavior of cd'ing the current shell into the
  workspace (that's the point of making it the interface; the no-cd rule was
  specific to `code`).

## Changes
1. `.zshrc`
   - Delete the entire `code()` function.
   - Keep `_jj_primary_root` (still used by the `wt remove` wrapper) and the
     `wt()` wrapper as-is (`remove` interception + plain `djo` delegation —
     bare `wt switch` needs no wrapper help since dojjo picks internally).
   - Guard messages: `guard on` refusal and `guard status` unmanaged text:
     "code/wt workspaces" → "wt workspaces".
2. `tools/herdr-cd-guard/status.sh`
   - unmanaged body: "open via code/wt switch to enable" → "open via wt switch
     to enable".

No changes to dojjo config, herdr-ws, or tests.

## Verification
1. `zsh -n .zshrc`; fresh interactive shell: `functions code` → not defined.
2. Live: `wt switch <existing>` from a repo → shell cd's into workspace +
   herdr workspace focused/created + guard armed (`cd ~` blocked there).
3. `wt switch -c <new>` → created, herdr workspace opens, guard armed;
   `wt remove <new>` → closes herdr workspace + disarms.
4. Bare `wt switch` → fzf picker appears (manual check by user).
